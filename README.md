# ديمو — شات بوت سياحي بالذكاء الاصطناعي (مشروع كلية)

الاسم اختصار **ديمتريوس الفاليري**، الذي تُنسب إليه فكرة مكتبة الإسكندرية القديمة.

مساعد سياحي لمصر يشتغل **بالكامل على جهازك**: مفيش API مدفوع، مفيش كريديت يخلص، ومفيش مفاتيح.

## البوت بيعمل إيه

| الدور | مثال |
|---|---|
| مرشد سياحي | "احكيلي عن قلعة قايتباي" |
| مخطط رحلات | "أروح فين في إسكندرية في يومين؟" |
| الطقس | "الجو عامل إيه في أسوان؟" |
| حجز فنادق وجولات | "عايز فندق في الأقصر بأقل من 2000 جنيه" |
| خدمة عملاء | الاستعلام عن حجز، إلغاؤه، أو التحويل لموظف |

بيرد بنفس لغة السائل: مصري، عربي فصحى، أو إنجليزي.

## صفحات الموقع

| الصفحة | بتعمل إيه |
|---|---|
| المحادثة | رد مباشر، وصورة وخريطة مع الرد عن أي مكان معروف، أسئلة متابعة مقترحة، تقييم لكل رد، "اسمع الرد"، مشاركة واتساب، "احفظ في رحلتي"، والسؤال بصوت أو بصورة (مع الموديل السحابي) |
| مخطط الرحلة | برنامج يوم بيوم بمواعيد: الأماكن مرتبة بالأقرب فالأقرب، ولكل زيارة مدة تقديرية، مع استراحة غداء ومسافة ووقت السيارة بين كل محطتين، وخريطة عليها خط المسار. ومعه "قريب مني" وقائمة "رحلتي" |
| أدوات السفر | الميزانية بثلاثة مستويات (اقتصادي، متوسط، فاخر) شاملة الأكل والمواصلات والتذاكر، العملات، المواصلات بين المدن، قائمة الشنطة، مواعيد الصلاة والإجازات، عبارات مصرية |
| الإحصائيات | الأسئلة والحجوزات والتقييمات ومصدر كل إجابة ونتائج الاستبيان |
| عن المشروع | طريقة العمل، الأدوات، الحدود، التقييم الآلي للدقة، واستبيان رأي الزوار |

البوت بيفتكر اسم المسافر ولو معاه أطفال طول المحادثة، وبيصحح الأخطاء الإملائية في أسماء الأماكن، وبيفهم طلب رحلة كامل في جملة واحدة (مثل: "3 أيام في الأقصر بميزانية 12000 جنيه مع طفلين") ويرد ببرنامج وتكلفة تقريبية. في الشريط الجانبي: زرار اللغة (العربية / English / Français؛ الفرنسية للواجهة فقط والردود بالعربية أو الإنجليزية)، الأسئلة الشائعة، الحجز السريع، وتنزيل تذكرة الحجز.

## التقييم الآلي للدقة

```
python evaluate.py
```

بيشغّل 70 سؤالًا من `data/eval.json` ويتأكد إن البوت وصل للموضوع الصحيح أو الإجابة المخزنة أو الأداة الصحيحة. النتيجة الحالية **94.3% (66 من 70)**.

| المرحلة | النتيجة | اللي اتعمل |
|---|---|---|
| أول 34 سؤال | 33 من 34 | كشف إن "What can you do?" ما بيتعرفش عليه، واتصلح |
| بعد إضافة 36 سؤال أصعب (لهجات، أخطاء إملائية، كلمة واحدة، مواضيع جديدة) | 59 من 70 (84.3%) | ظهرت 3 مشاكل عامة في البحث |
| بعد تصحيح الإملاء، أولوية عنوان الموضوع، وكلمات الحشو في اللهجات | 66 من 70 (94.3%) | |

الأربعة اللي لسه بيفشلوا متسابين زي ما هم ومكتوبين في ناتج البرنامج: أسئلة صياغتها بعيدة عن كلمات الموضوع (مثل "ينفع اصور جوه المعابد")، وسؤال باللهجة الشامية.

حدود المقياس: الأسئلة كتبها صاحب المشروع نفسه، وبيقيس التوجيه والاسترجاع في الوضع البسيط مش صياغة رد الموديل. فهو بيضمن إن التعديلات ما بتكسرش اللي كان شغال، ومش حكم محايد على الجودة.

لإضافة سؤال للتقييم ضيف سطر في `data/eval.json` بنوع `topic` أو `faq` أو `tool`.

## بوت تليجرام

نفس المخ على تليجرام من ملف `telegram_bot.py`:

1. في تليجرام كلّم @BotFather واكتب `/newbot` وخد الـ token.
2. حطه في متغير بيئة اسمه `TELEGRAM_BOT_TOKEN` (ما تكتبوش في الكود).
3. شغّل `python telegram_bot.py` وسيبه مفتوح.

بيشتغل على جهازك طول ما الملف شغال، ومش بيشتغل من موقع Streamlit نفسه.

## تشغيل الذكاء الاصطناعي على الموقع المنشور (اختياري ومجاني)

الاستضافة المجانية لا تشغّل موديل محلي، لكن الموقع يقدر يستخدم موديل سحابي بمفتاح مجاني:

1. اعمل حساب على console.groq.com وأنشئ API key.
2. في Streamlit Cloud: افتح إعدادات التطبيق (Settings) ثم Secrets، واكتب:
   ```
   GROQ_API_KEY = "المفتاح هنا"
   ```
3. احفظ. الموقع يتحول لوضع الذكاء الاصطناعي، وتشتغل معه **الرسائل الصوتية** و**السؤال بصورة**.

لا تكتب المفتاح في الكود أو على GitHub. اسم الموديل الافتراضي `llama-3.3-70b-versatile`؛ لو الخدمة غيّرت أسماء موديلاتها أضف `CLOUD_MODEL = "الاسم الجديد"` في Secrets. الباقة المجانية لها حد يومي، ولو خلصت الموقع يرجع تلقائيًا للوضع البسيط.

لعرض نصوص الأسئلة في صفحة الإحصائيات أضف `ADMIN_PASSWORD = "كلمة سر"` في Secrets؛ بدونها تظهر الأرقام فقط حفاظًا على خصوصية الزوار.

## أسرع تشغيل (دقائق، بدون تحميل موديل)

محتاج Python فقط:

- **ويندوز:** دبل كليك على `run.bat`
- **ماك / لينكس:** `bash run.sh`

أو يدويًا:
```
pip install -r requirements.txt
streamlit run app.py
```

البوت هيفتح في **الوضع البسيط**: يجاوب من قاعدة المعرفة، ويعرض الطقس والفنادق والجولات، ويستعلم عن الحجوزات ويلغيها، ويفتح تذاكر خدمة العملاء، والحجز من نموذج "حجز سريع" في الشريط الجانبي. ده بيضمن إن عندك حاجة شغالة للعرض مهما حصل.

أول ما Ollama والموديل يبقوا جاهزين، البوت يتحول **تلقائيًا** لوضع الذكاء الاصطناعي: محادثة حرة، برامج رحلات مفصلة على طلبك، وحجز بالكلام داخل الشات.

## تشغيله كموقع على الإنترنت (مجانًا)

المشروع جاهز للنشر على **Streamlit Community Cloud** من GitHub مباشرة:

1. ارفع المشروع على GitHub (مستودع عام أو خاص).
2. افتح share.streamlit.io وسجّل الدخول بحساب GitHub.
3. اختر **Create app**، ثم المستودع، الفرع `main`، والملف الرئيسي `app.py`.
4. اضغط **Deploy**. بعد دقائق تحصل على رابط عام يفتح من أي جهاز أو موبايل.

ملاحظات مهمة:

- النسخة المنشورة تعمل بـ **الوضع البسيط**، لأن الاستضافة المجانية لا تشغّل نموذجًا لغويًا. وضع الذكاء الاصطناعي يعمل على جهازك فقط.
- قاعدة البيانات مشتركة بين كل زوار الموقع: أي حجز تجريبي (واسم صاحبه) يظهر للجميع في الشريط الجانبي، ويُمسح عند إعادة تشغيل الموقع. لا تكتب بيانات حقيقية.

## تشغيل وضع الذكاء الاصطناعي (مرة واحدة)

1. نزّل **Python 3.10 أو أحدث** من python.org.
2. نزّل **Ollama** من ollama.com وافتحه.
3. حمّل الموديلات (في التيرمنال / CMD):
   ```
   ollama pull qwen2.5:7b
   ollama pull bge-m3
   ```
   لو الجهاز رامه أقل من 16GB استخدم `ollama pull qwen2.5:3b` بدل الأول (شوف "جهاز ضعيف" تحت).
4. افتح التيرمنال جوه فولدر المشروع ونزّل المكتبات:
   ```
   pip install -r requirements.txt
   ```
5. اتأكد إن كل حاجة جاهزة:
   ```
   python check_setup.py
   ```

## التشغيل كل مرة

```
streamlit run app.py
```
هيفتح المتصفح على الشات. أول رسالة بتاخد وقت أطول شوية لأن الموديل بيتحمّل في الرام.

### جهاز ضعيف
قبل `streamlit run app.py` اكتب:

- ويندوز (CMD): `set CHAT_MODEL=qwen2.5:3b` ثم `set NUM_CTX=4096`
- ماك / لينكس: `export CHAT_MODEL=qwen2.5:3b NUM_CTX=4096`

الموديل الأصغر أسرع لكنه أقل دقة في استدعاء أدوات الحجز.

## مصادر البيانات

| المصدر | بيُستخدم في |
|---|---|
| قاعدة المعرفة المحلية (114 موضوعًا) | الأماكن والنصائح وبرامج الرحلات، وهي المصدر الأول دائمًا |
| ويكيبيديا العربية + Wikipedia الإنجليزية | أي موضوع غير موجود في قاعدة المعرفة |
| Wikivoyage (دليل سفر) | بديل للأسئلة الإنجليزية |
| Open-Meteo + wttr.in | الطقس |
| SQLite | الفنادق والجولات والحجوزات |

البوت يسأل المصادر الخارجية فقط لما تكون مطابقة السؤال لقاعدة المعرفة ضعيفة، ويذكر المصدر ورابطه تحت الرد. كلها مجانية وبدون مفتاح، وتحتاج إنترنت.

## إزاي بيشتغل (للمناقشة)

```
رسالة السائح
     │
     ▼
1) البحث في قاعدة المعرفة (RAG)  ──►  أقرب 4 مواضيع لسؤاله
     │
     ▼
2) الموديل المحلي (Qwen2.5 عبر Ollama) يقرأ السؤال + المواضيع
     │
     ├── رد مباشر (معلومة / برنامج رحلة)
     │
     └── استدعاء أداة (Tool calling):
           get_weather        ← Open-Meteo، و wttr.in كبديل (مجاني بدون مفتاح)
           search_hotels / search_tours / create_booking
           get_booking / cancel_booking          ← SQLite
           handoff_to_human   ← تذكرة لموظف خدمة العملاء
     │
     ▼
3) الموديل يصيغ الرد النهائي بلغة السائح
```

لو الموديل غير متاح، الخطوة 2 تُستبدل بـ **الوضع البسيط**: تحديد نية السائل بالكلمات المفتاحية ثم استخدام نفس قاعدة المعرفة ونفس الأدوات.

- **RAG:** الموديل ما بيألفش معلومات الأماكن؛ بيجاوب من `data/knowledge.json`. البحث دلالي بموديل `bge-m3` (بيفهم العربي والإنجليزي)، ولو الموديل ده مش متاح البوت بيتحول تلقائيًا لبحث بالكلمات (BM25).
- **Tool calling:** الأسعار والحجوزات والطقس بتيجي من أدوات حقيقية مش من خيال الموديل.

## إضافة أسئلة شائعة

الأسئلة الشائعة في ملف نصي بسيط: `data/faq.txt`. البوت بيرد عليها بالإجابة المكتوبة حرفيًا، وأول صيغة من كل سؤال بتظهر كزرار في الموقع.

```
س: بتقبلوا الدفع بالفيزا؟
س: ينفع أدفع بالكارت؟
ج: الحجز هنا تجريبي ومفيش دفع حقيقي.
```

- سطر فاضي بين كل سؤال والتاني.
- تقدر تكتب أكتر من سطر `س:` لنفس السؤال بصيغ مختلفة، وكل ما زادت الصيغ البوت بيتعرف على السؤال أحسن.
- للتعديل من غير برامج: افتح الملف على GitHub، اضغط علامة القلم (Edit)، ضيف السؤال، ثم Commit changes. الموقع بيتحدث لوحده بعد دقيقة تقريبًا.

## إضافة معلومات جديدة

افتح `data/knowledge.json` وأضف موضوعًا بنفس الشكل (`id`, `title_ar`, `title_en`, `city`, `category`, `text`). البوت بيعيد بناء الفهرس لوحده عند التشغيل التالي.

## حدود المشروع (قلها بصراحة في المناقشة)

- الفنادق والجولات والأسعار **بيانات تجريبية وهمية**، والحجز لا يتضمن دفعًا حقيقيًا.
- معلومات الأماكن مكتوبة كمعرفة عامة؛ أسعار التذاكر والمواعيد غير مذكورة عمدًا لأنها تتغير، والبوت يوجّه السائح للمصدر الرسمي. راجع محتوى قاعدة المعرفة قبل التسليم.
- الطقس هو الجزء الوحيد المحتاج إنترنت؛ باقي البوت يشتغل أوفلاين.
- إجابات ويكيبيديا تُعرض كما هي (مقدمة المقال) وقد لا تجيب السؤال بالضبط؛ البوت في الوضع البسيط يبحث عن الموضوع ولا يستنتج.
- الوضع البسيط لا يفهم إلا الأسئلة المباشرة ولا يؤلف برامج رحلات جديدة؛ يعرض الموضوع الأقرب من قاعدة المعرفة كما هو (بالعربية حتى لو السؤال بالإنجليزية).
- الموديلات المحلية الصغيرة أضعف من النماذج السحابية الكبيرة، وقد تخطئ أحيانًا في استدعاء الأدوات.

بوت تليجرام أو واتساب، سؤال عن أثر من صورته، تقييم آلي لدقة الردود، وربط بنظام حجز ودفع حقيقي.
